# Реєстрація та вхід через Supabase Auth

GitHub Pages роздає лише статичні файли. Облікові записи створюються в окремому проєкті Supabase Auth. Без налаштованого проєкту реєстрація неактивна; сайт не створює локальні облікові записи й не зберігає паролі в браузері.

## Підключення

1. Створіть або виберіть проєкт у Supabase. У **Authentication → Providers / Sign In** увімкніть Email.
2. У **Authentication → URL Configuration** встановіть Site URL та дозволений Redirect URL:
   `https://systemh4rd.github.io/HomeDos/`
3. Залиште підтвердження електронної пошти ввімкненим. Для реальних користувачів налаштуйте SMTP відповідно до вимог і лімітів вашого проєкту Supabase.
4. У **Project Settings → API / API Keys** скопіюйте URL проєкту та **publishable key** (або legacy `anon` key).
5. Заповніть відповідні поля в `docs/auth-config.js`. Ці значення публічні за задумом Supabase. Не використовуйте `service_role`, `sb_secret_…`, пароль PostgreSQL чи інші серверні секрети.
6. Опублікуйте зміни в `main`. Якщо змінюєте конфігурацію після попередньої публікації, оновіть версію `auth-config.js` у `docs/index.html`, щоб браузер завантажив нові налаштування.

Створення акаунтів, вхід, відновлення пароля та оновлення сесії виконує Supabase. Для підключення можна також використати інтеграцію Supabase у ChatGPT; приватні серверні ключі для роботи сайту не потрібні.

## Межі зберігання

Реєстрація не вмикає хмарну синхронізацію дошок. Гостьовий режим і кожен підтверджений обліковий запис мають окремий простір у сховищі цього браузера. Після виходу відкривається гостьовий простір. Дані не переносяться між пристроями автоматично; використовуйте JSON-експорт та імпорт.
