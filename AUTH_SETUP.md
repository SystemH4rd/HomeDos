# Реєстрація та вхід через Supabase Auth

GitHub Pages роздає лише статичні файли. Облікові записи створюються в окремому проєкті Supabase Auth. Без налаштованого проєкту реєстрація неактивна; сайт не створює локальні облікові записи й не зберігає паролі в браузері.

## Підключення

1. Створіть або виберіть проєкт у Supabase. У **Authentication → Providers / Sign In** увімкніть Email.
2. У **Authentication → URL Configuration** встановіть Site URL та дозволений Redirect URL:
   `https://systemh4rd.github.io/HomeDos/`
3. Залиште підтвердження електронної пошти ввімкненим. Для реальних користувачів налаштуйте SMTP відповідно до вимог і лімітів вашого проєкту Supabase.
4. У **Project Settings → API / API Keys** скопіюйте URL проєкту та **publishable key** (або legacy `anon` key).
5. Заповніть відповідні поля в `docs/auth-config.js`. Ці значення публічні за задумом Supabase. Не використовуйте `service_role`, `sb_secret_…`, пароль PostgreSQL чи інші серверні секрети.
6. Опублікуйте зміни в `main`. Якщо змінюєте конфігурацію після попередньої публікації, оновіть версію `auth-config.js` у `docs/index.html`, щоб браузер завантажив нові налаштування.

Створення акаунтів, вхід, відновлення пароля та оновлення сесії виконує Supabase. Для підключення можна також використати інтеграцію Supabase у ChatGPT; приватні серверні ключі для роботи сайту не потрібні.

## Онлайн-збереження дошок і вкладень

7. У Supabase **SQL Editor** виконайте [supabase/schema.sql](supabase/schema.sql). Він створить таблицю приватних робочих просторів, атомарну функцію збереження та приватний bucket `orbit-files` (до 20 МБ на файл). RLS дозволяє користувачу читати лише власний простір і вкладення; запис дошки йде через функцію з перевіркою версії.
8. Перевірте сайт: зареєструйте пошту, підтвердьте її, увійдіть, змініть дошку та дочекайтеся **«Збережено онлайн»**. Увійдіть тим самим акаунтом в іншому браузері: дошки й вкладення мають завантажитися. Перевірте вихід, відновлення пароля та відсутність доступу іншого акаунта до цих даних.

Після входу зберігається весь простір: дошки, блоки, зв’язки, завдання та вкладення. Гостьові дошки залишаються локальними; перенесіть потрібні через JSON-експорт та імпорт після входу. Наявні локальні дошки профілю завантажуються в порожню хмару. Якщо в хмарі вже є інша версія, застосунок збереже локальні зміни та покаже конфлікт замість перезапису.

Збереження запускається через 700 мс після зміни. Під час збою локальна копія залишається в браузері; доступна кнопка повторної синхронізації. Повернення мережі також запускає повторну спробу. Позначка **«Збережено онлайн»** означає завершення завантаження вкладень і запису дошок. До цього не очищуйте дані браузера.

При конфлікті кнопка **«Відкрити хмарну копію»** після підтвердження завантажує JSON резервної копії локального простору разом із вкладеннями та зберігає її в `localStorage` під ключем `orbit.cloud.v1.<user-id>.backup`. Цю копію можна відновити кнопкою «Імпортувати дошку» (до 80 МБ): усі її дошки додаються до поточного простору. Якщо вкладення недоступне або простір змінюється під час створення копії, хмарна версія не замінить локальну. Серверний простір обмежено 10 МБ JSON; вкладення зберігаються окремо. Автоматичного видалення невикористаних вкладень та спільного редагування в реальному часі немає.

## Підключений проєкт HomeDos

Підключено проєкт `zyqfgvdsuvcrwgpreqoy` в організації `afkgreem`, регіон Frankfurt (`eu-central-1`). SQL-схему застосовано, приватний bucket створено, публічний publishable key внесено в конфігурацію сайту. Реєстрація email увімкнена, підтвердження пошти обов’язкове.

У [налаштуваннях URL Auth](https://supabase.com/dashboard/project/zyqfgvdsuvcrwgpreqoy/auth/url-configuration) потрібно встановити Site URL і Redirect URL `https://systemh4rd.github.io/HomeDos/`. Ці налаштування не доступні через підключені інструменти Supabase. Для реєстрації користувачів поза командою організації потрібно підключити власний SMTP у [налаштуваннях пошти](https://supabase.com/dashboard/project/zyqfgvdsuvcrwgpreqoy/auth/smtp). Стандартний сервіс Supabase має обмеження адресатів і ліміти.

Після міграції перевірено RPC запису й читання, збільшення ревізії, відмову застарілій ревізії та ізоляцію двох користувачів у транзакції з rollback; тестових акаунтів і дошок не залишено. Live email-підтвердження ще потребує перевірки після URL/SMTP.

Security Advisor позначає RPC `orbit_save_workspace` як SECURITY DEFINER, доступний authenticated. Це свідомий обмежений API для атомарного збереження: user_id береться тільки з `auth.uid()`, порожній search_path, анонімний виклик і прямі INSERT/UPDATE таблиці заборонені. Документація: https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable
